# Code Wiki Schema

This wiki documents the **codebase itself**. It does not track the semantic content produced by transcription jobs.

## Layers

- **Raw sources**: `src/`, `tests/`, `README.md`, `.omx/plans/`, `.claude/project-context/`, `.agents/skills/`, and `.claude/skills/`. These remain the source of truth.
- **Deterministic evidence**: `docs/wiki/evidence/`. Generated by the CLI. This layer is overwritten by `init`, `refresh`, and `ingest`.
- **Refined pages**: `docs/wiki/pages/`. Maintained by an LLM or a human. This layer is never overwritten by the deterministic CLI once scaffolded.
- **Schema**: this file plus [Refinement Playbook](./refinement-playbook.md). They define how future sessions should operate on the two layers.

## Canonical files

- [Index](./index.md): top-level navigation for the whole wiki.
- [Refinement Playbook](./refinement-playbook.md): rigid rules for turning evidence into durable project docs.
- [Evidence Index](./evidence/index.md): catalog of deterministic evidence pages.
- [Refined Pages Index](./pages/index.md): catalog of LLM-maintained refined pages.
- [Log](./log.md): append-only operational history covering deterministic updates and refinement passes.

## Ownership rules

- The CLI owns `docs/wiki/evidence/`, `docs/wiki/schema.md`, `docs/wiki/refinement-playbook.md`, the top-level `index.md`, and `log.md`.
- The LLM owns `docs/wiki/pages/` and should treat it as the durable synthesis layer.
- Never hand-edit `docs/wiki/evidence/`. If the evidence is stale, run `npm run wiki -- ingest` or `npm run wiki -- refresh`.
- Never let the deterministic CLI overwrite refined pages in `docs/wiki/pages/`.

## Deterministic workflow

### Init / Refresh

- Generate or refresh the evidence pages under `docs/wiki/evidence/`.
- Rebuild the top-level `index.md` and `docs/wiki/evidence/index.md`.
- Ensure `docs/wiki/pages/index.md` exists, but do not overwrite it if it already contains refined content.
- Append a chronological entry to `log.md`.

### Ingest

- Use `npm run wiki -- ingest --source <path>` after relevant code, test, or documentation changes.
- Update only evidence pages whose `source_paths` overlap the changed files.
- Rebuild the indexes owned by the deterministic layer.
- Append a chronological entry to `log.md`.

### Query

- Use `npm run wiki -- query --query "<terms>"` to search across both `evidence/` and `pages/`.
- Prefer refined pages when they exist, then verify against evidence pages and raw sources.
- When the scope is unclear, start from [Index](./index.md), then [Refined Pages Index](./pages/index.md), then [Evidence Index](./evidence/index.md).

### Lint

- Use `npm run wiki -- lint` to detect:
  - missing required deterministic pages
  - pages missing from any wiki index
  - orphan pages with no inbound wiki links
  - broken internal markdown links

## Refinement workflow

- Read [Refinement Playbook](./refinement-playbook.md) before writing or revising refined pages.
- Refine evidence into `docs/wiki/pages/`, not into `docs/wiki/evidence/`.
- If a session produces durable project knowledge, file it into `docs/wiki/pages/`, update `docs/wiki/pages/index.md`, and append a `refine` entry to `log.md`.
