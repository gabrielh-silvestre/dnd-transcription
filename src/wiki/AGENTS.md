# wiki

## Purpose
A **self-contained code-wiki maintenance CLI** that generates and queries the repo's documentation layer in `docs/wiki/`. It is independent of the transcription pipeline — it imports only `src/shared/` utilities and never touches the transcription domain/application/infrastructure. Run via `npm run wiki -- <init|refresh|ingest|query|lint>`.

It mirrors the main app's hexagonal layering, though only three layers carry code today.

## Subdirectories
| Directory | Purpose |
|-----------|---------|
| `application/` | Core logic: repo snapshot collection, page definitions/generators, and the `CodeWikiService` (see `application/AGENTS.md`) |
| `cli/` | Argument parsing, command dispatch, result rendering, entrypoint (see `cli/AGENTS.md`) |
| `shared/` | `wiki-paths.ts` — wiki directory layout constants & path helpers (see `shared/AGENTS.md`) |
| `domain/`, `infrastructure/` | **Empty scaffolding** (0 files). Reserved for future ports/adapters; no AGENTS.md generated. |

## For AI Agents

### Working In This Directory
- This subsystem **writes** `docs/wiki/`. The evidence layer (`docs/wiki/evidence/`) is deterministically regenerated by `init`/`refresh`/`ingest`; the refinement layer (`docs/wiki/pages/`) is preserved and never auto-overwritten.
- Command → service-method mapping: `init`→`init()`, `refresh`→`refresh()`, `ingest`→`ingest()`, `query`→`query()`, `lint`→`lint()`.
- Help text and messages are in Portuguese.
- Don't reach into transcription layers — keep the wiki standalone (only `src/shared/` is fair game).

### Testing Requirements
Covered by `tests/unit/wiki/code-wiki-service.test.ts` and `wiki-argument-parser.test.ts`, which build fixture repo trees in temp dirs.
